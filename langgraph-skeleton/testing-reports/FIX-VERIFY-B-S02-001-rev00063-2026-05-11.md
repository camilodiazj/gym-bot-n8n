## Logs Cloud Run — defensa en profundidad funcionando

### Layer 1: hard filter en `get_exercises_for_draft`

13 warnings de patterns omitidos (cobertura DB insuficiente):

```
[EQUIPMENT] No exercises for pattern=pull_v match equipment=['bodyweight', 'peso corporal']. (13 candidates dropped). Pattern will be omitted from draft.
[EQUIPMENT] No exercises for pattern=pull_h match equipment=['bodyweight', 'peso corporal']. (12 candidates dropped). Pattern will be omitted from draft.
[EQUIPMENT] No exercises for pattern=hinge match equipment=['bodyweight', 'peso corporal']. (4 candidates dropped). Pattern will be omitted from draft.
... (10 more)
```

El LLM ve la lista vacía y, siguiendo el system prompt *"Si un patrón no devuelve resultados, omítelo"*, omite el patrón. Resultado: rutina más corta pero correcta.

### Layer 2: `save_workout_plan` validation

```
[EQUIPMENT] save_workout_plan rejected for user_id=56cb3514-f064-4bff-9e06-685304004b03: 4 exercise(s) violate allowed_equip=['bodyweight', 'peso corporal']
```

**El primer intento del LLM incluyó 4 ejercicios con equipment inválido** (probablemente machine/dumbbell). La validación los rechazó con `EQUIPMENT_MISMATCH`, el LLM reintentó con la guía del hint, y la segunda vez guardó 48 workouts válidos.

Esto confirma que **el LLM puede "hallucinar" ejercicios fuera del filtro** — la red de seguridad en `save_workout_plan` es necesaria.

---

## Por qué funcionó el approach

1. **Single source of truth** (`_user_allowed_equipment`) — los 3 puntos de validación leen del mismo set
2. **Fail loud en filter** — el LLM ve el filtro reflejado en la respuesta (lista vacía)
3. **Hard rejection en save** — el LLM no puede "saltarse" el filtro inventando nombres
4. **Bug visible** — los 13 warnings de pattern omitido apuntan exactamente a `pull_v`, `pull_h`, `hinge` como gaps de cobertura DB
