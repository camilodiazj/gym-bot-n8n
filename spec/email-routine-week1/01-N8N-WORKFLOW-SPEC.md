## 1. Overview

This specification adds 4 new nodes to the `WORKOUT_CREATOR.json` workflow as a **parallel branch** from the existing "Create a row" node. The purpose is to email the user their Week 1 routine as a formatted HTML document immediately after workout creation.

### Design Principles

- **Parallel execution:** The email branch runs in parallel with the existing WhatsApp notification + return flow. It does NOT block or delay the existing path.
- **Fault isolation:** If any node in the email branch fails, the existing flow (WhatsApp notification via `NotifyRoutineCreated` and return via `Filtered Message2`) continues unaffected.
- **No modifications to existing nodes:** All 4 nodes are additive. The only change to an existing node is adding a second output connection from "Create a row".

### Current Flow (End Section)

```
ValidateWorkoutDuration --> Create a row --> NotifyRoutineCreated --> Filtered Message2 (return)
                            [1312, 144]      [1552, 144]             [1760, 160]
```

### New Flow (After Change)

```
                                          +--> NotifyRoutineCreated --> Filtered Message2 (return)
                                          |    [1552, 144]             [1760, 160]
Create a row  ---(parallel output)--------+
[1312, 144]                               |
                                          +--> GetWeek1WithExercises --> GenerateRoutineHTML --> HasEmail --> SendRoutineEmail
                                               [1552, 400]              [1760, 400]            [1968, 400]   [2176, 400]
```

Both branches execute simultaneously from "Create a row". The workflow completes when both branches finish.

## 2. Node 1: GetWeek1WithExercises

### Purpose

Retrieves all Week 1 exercises for the newly created user, joined with the `exercises` table to get display-friendly metadata (Spanish names, muscle groups, equipment, video links). The items flowing through "Create a row" only contain raw workout data (`exercise_id`, `sets`, `reps`, etc.) without the exercise catalog metadata needed for a readable email.

### Full n8n Node JSON

```json
{
  "parameters": {
    "operation": "executeQuery",
    "query": "SELECT w.day_name, w.exercise_order, w.sets, w.reps, w.rir, w.\"rest-seconds\" as rest_seconds, w.tempo, e.spanish_name, e.main_muscle, e.secondary_muscles, e.equipment, e.link, e.role FROM workouts w JOIN exercises e USING(exercise_id) WHERE w.user_id = '{{ $items('GetUser')[0].json.user_id }}' AND w.week = 1 ORDER BY CASE w.day_name WHEN 'Push' THEN 1 WHEN 'Pull' THEN 2 WHEN 'Legs' THEN 3 WHEN 'Upper' THEN 4 WHEN 'Upper (Arms)' THEN 4 WHEN 'Lower' THEN 5 WHEN 'Lower (Glutes)' THEN 5 WHEN 'Full Body' THEN 6 END, w.exercise_order",
    "options": {}
  },
  "type": "n8n-nodes-base.postgres",
  "typeVersion": 2.6,
  "position": [1552, 400],
  "id": "<auto-generated>",
  "name": "GetWeek1WithExercises",
  "executeOnce": true,
  "credentials": {
    "postgres": {
      "id": "vZLJtIWG5nYXMez4",
      "name": "Supabase Memory"
    }
  }
}
```

### Query Explanation

| Clause | Reason |
|--------|--------|
| `JOIN exercises e USING(exercise_id)` | Fetches `spanish_name`, `main_muscle`, `secondary_muscles`, `equipment`, `link`, `role` from the exercise catalog |
| `w.user_id = '{{ $items('GetUser')[0].json.user_id }}'` | References the user created/found earlier in the workflow via the `GetUser` node |
| `w.week = 1` | Only retrieves Week 1 exercises (the email shows the first week only) |
| `ORDER BY CASE w.day_name ... END, w.exercise_order` | Ensures training days appear in logical order (Push, Pull, Legs, Upper, Lower, Full Body) and exercises are ordered within each day (compound first, then core, then isolation) |
| `w."rest-seconds" as rest_seconds` | The column name has a hyphen, requiring quoting. Alias to `rest_seconds` for clean JavaScript access |

### Credential Reference

This uses the same Postgres credential (`id: "vZLJtIWG5nYXMez4"`, name: `"Supabase Memory"`) already used by the `LoadProfile` and `GetExercisesByPattern` nodes in this workflow. No new credential setup is needed.

### Why This Query Pattern

This same JOIN pattern exists in `MAIN_FLOW.json` at the `Tool_Get_Workout2` node (line 224-225):

```sql
select day_name as session_name, week, spanish_name, main_muscle, reps, sets, rir, link, "rest-seconds"
from workouts join exercises using(exercise_id)
where user_id = '...' and day_name = '...' and week = ...
order by exercise_order
```

Our query extends this pattern by:
1. Selecting additional columns: `exercise_order`, `tempo`, `secondary_muscles`, `equipment`, `role`
2. Not filtering by `day_name` (we want ALL days for Week 1)
3. Ordering by `day_name` first, then `exercise_order`

### Node Configuration Details

| Property | Value | Reason |
|----------|-------|--------|
| `executeOnce` | `true` | Prevents re-execution per input item. The query already returns all exercises. |
| `typeVersion` | `2.6` | Matches the Postgres node version used elsewhere in this workflow |
| `position` | `[1552, 400]` | Placed directly below `NotifyRoutineCreated` ([1552, 144]) with 256px vertical offset for visual clarity |

### Expected Output

An array of 15-35 items (varies by `days_available`: 3-day plans produce ~15 exercises, 6-day plans produce ~30-35). Each item contains:

```json
{
  "day_name": "Push",
  "exercise_order": 1,
  "sets": "3",
  "reps": "10-12",
  "rir": "3",
  "rest_seconds": 90,
  "tempo": "2-0-2-0",
  "spanish_name": "Press de Banca con Barra",
  "main_muscle": "Chest",
  "secondary_muscles": ["Triceps", "Shoulders"],
  "equipment": "barbell",
  "link": "https://musclewiki.com/es-es/exercise/...",
  "role": "compound"
}
```

### Edge Cases

| Scenario | Behavior |
|----------|----------|
| User has no week 1 workouts (should never happen at this point) | Returns empty array. `GenerateRoutineHTML` receives empty input. |
| Database connection timeout | Node fails, email branch dies silently. WhatsApp branch unaffected. |

## 4. Node 3: HasEmail

### Purpose

Guards the email send operation. Checks whether the user provided an email during KYC onboarding. If no email exists (null, undefined, or empty string), the flow stops here without error.

### Full n8n Node JSON

```json
{
  "parameters": {
    "conditions": {
      "options": {
        "caseSensitive": true,
        "leftValue": "",
        "typeValidation": "strict",
        "version": 3
      },
      "conditions": [
        {
          "id": "<auto-generated>",
          "leftValue": "={{ $json.email }}",
          "rightValue": "",
          "operator": {
            "type": "string",
            "operation": "exists",
            "singleValue": true
          }
        }
      ],
      "combinator": "and"
    },
    "options": {}
  },
  "type": "n8n-nodes-base.if",
  "typeVersion": 2.3,
  "position": [1968, 400],
  "id": "<auto-generated>",
  "name": "HasEmail"
}
```

### Condition Logic

| Condition | Evaluates To | Outcome |
|-----------|-------------|---------|
| `$json.email` is a non-empty string (e.g., `"user@gmail.com"`) | `true` | **True branch (index 0):** Proceeds to `SendRoutineEmail` |
| `$json.email` is `null`, `undefined`, or `""` | `false` | **False branch (index 1):** Dead end (no connection). Flow terminates silently. |

### Why This Guard Is Necessary

The `email` column in the `users` table is nullable. Users who complete KYC via WhatsApp may not provide an email address. The `users_gym_profile` table also has an `email` field that may be empty. Without this guard, the `SendRoutineEmail` node would attempt to send to a null/empty address, causing an SMTP error.

### Node Configuration Details

| Property | Value | Reason |
|----------|-------|--------|
| `typeVersion` | `2.3` | Standard IF node version |
| `position` | `[1968, 400]` | Continues the horizontal flow from `GenerateRoutineHTML` |

## 5. Node 4: SendRoutineEmail

### Purpose

Sends the formatted HTML email to the user via SMTP. This is the terminal node of the email branch.

### Full n8n Node JSON

```json
{
  "parameters": {
    "fromEmail": "kairos@gymbot.fit",
    "toEmail": "={{ $json.email }}",
    "subject": "={{ $json.subject }}",
    "html": "={{ $json.html }}",
    "options": {
      "appendAttribution": false
    }
  },
  "type": "n8n-nodes-base.emailSend",
  "typeVersion": 1,
  "position": [2176, 400],
  "id": "<auto-generated>",
  "name": "SendRoutineEmail",
  "executeOnce": true,
  "continueOnFail": true,
  "credentials": {
    "smtp": {
      "id": "<CONFIGURE_IN_N8N_UI>",
      "name": "GymBot Email SMTP"
    }
  }
}
```

### Critical Configuration Notes

| Property | Value | Why |
|----------|-------|-----|
| `continueOnFail` | `true` | **CRITICAL.** If SMTP fails (auth error, timeout, invalid address, rate limit), the workflow MUST continue without throwing an error. Without this, an SMTP failure would propagate up and could affect the parallel WhatsApp branch. |
| `executeOnce` | `true` | Only one email per workflow execution |
| `appendAttribution` | `false` | Do not append n8n branding to the email |

### fromEmail Configuration

**IMPORTANT:** The `fromEmail` field MUST be set to the sender address configured in the SMTP credential, NOT `$json.email`. The `$json.email` is the recipient's address.

The n8n-agent must set the correct `fromEmail` based on the SMTP provider:

| SMTP Provider | fromEmail Value |
|---------------|----------------|
| Gmail | The Gmail address used for authentication (e.g., `gymbot.kairos@gmail.com`) |
| Resend | Any address on the verified domain (e.g., `kairos@gymbot.fit`) |
| Amazon SES | Any verified sender address |

If the SMTP credential is not yet configured, use a placeholder like `kairos@gymbot.fit` and update after credential setup.

### Data Flow Into This Node

| Field | Source Expression | Example Value |
|-------|-------------------|---------------|
| `toEmail` | `$json.email` | `"maria.lopez@gmail.com"` |
| `subject` | `$json.subject` | `"Tu Rutina Semana 1 - Kairos Personal Trainer"` |
| `html` | `$json.html` | Full HTML document string |

All three fields come from the output of `GenerateRoutineHTML`, passed through `HasEmail`.

**New connections (replace the above):**

```json
"Create a row": {

      {
        "node": "NotifyRoutineCreated",
        "type": "main",
        "index": 0
      },
      {
        "node": "GetWeek1WithExercises",
        "type": "main",
        "index": 0
      }
    ]
  ]
}
```

**Key detail:** Both connections are in the same inner array `[...]`, which means they execute in **parallel** (n8n fan-out behavior). If they were in separate inner arrays, they would represent different output indices (true/false branches), which is NOT what we want.

### 6.2 New Connection Entries

Add these 3 new entries to the `"connections"` object in the workflow JSON:

```json
"GetWeek1WithExercises": {
  "main": [

        "node": "GenerateRoutineHTML",
        "type": "main",
        "index": 0
      }
    ]
  ]
},
"GenerateRoutineHTML": {
  "main": [
    [
      {
        "node": "HasEmail",
        "type": "main",
        "index": 0
      }
    ]
  ]
},
"HasEmail": {
  "main": [
    [
      {
        "node": "SendRoutineEmail",
        "type": "main",
        "index": 0
      }

  ]
```

**HasEmail branching:** The first inner array `[{ "node": "SendRoutineEmail" ... }]` is the **true branch** (index 0). The second inner array `[]` is the **false branch** (index 1) -- empty, meaning no downstream node.

## 7. SMTP Credential Configuration

The `SendRoutineEmail` node requires an SMTP credential named `"GymBot Email SMTP"`. This must be created in the n8n UI before the email branch can function.

### Option A: Gmail SMTP (Recommended for MVP/Development)

**Step-by-step:**

1. **Enable 2-Step Verification** on the Google account:
   - Go to https://myaccount.google.com/security
   - Enable 2-Step Verification if not already active

2. **Generate an App Password:**
   - Go to https://myaccount.google.com/apppasswords
   - Select app: "Mail"
   - Select device: "Other (Custom name)" -> enter "GymBot n8n"
   - Copy the 16-character app password (format: `xxxx xxxx xxxx xxxx`)

3. **Create SMTP credential in n8n:**
   - Go to n8n Settings -> Credentials -> Add Credential -> SMTP
   - **Name:** `GymBot Email SMTP`
   - **Host:** `smtp.gmail.com`
   - **Port:** `587`
   - **SSL/TLS:** `STARTTLS`
   - **User:** `<gmail-address>@gmail.com`
   - **Password:** The 16-character app password from step 2 (spaces optional)

4. **Update `fromEmail` in SendRoutineEmail node** to match the Gmail address used.

**Limits:**
- Personal Gmail: 500 emails/day
- Google Workspace: 2,000 emails/day

### Option B: Resend (Recommended for Production)

**Step-by-step:**

1. **Sign up** at https://resend.com
2. **Add and verify sender domain:**
   - Go to Domains -> Add Domain
   - Add DNS records: SPF (`v=spf1 include:_spf.resend.com ~all`), DKIM (provided by Resend)
   - Wait for verification (usually < 5 minutes)
3. **Create API key:**
   - Go to API Keys -> Create API Key
   - Copy the key (starts with `re_`)
4. **Create SMTP credential in n8n:**
   - **Name:** `GymBot Email SMTP`
   - **Host:** `smtp.resend.com`
   - **Port:** `465`
   - **SSL/TLS:** `SSL`
   - **User:** `resend`
   - **Password:** The API key (`re_...`)
5. **Update `fromEmail`** to any address on the verified domain (e.g., `kairos@gymbot.fit`)

**Limits (Free Tier):**
- 100 emails/day
- 3,000 emails/month

### Option C: Amazon SES (For Scale)

**Step-by-step:**

1. **Go to AWS Console** -> Simple Email Service (SES)
2. **Verify sender domain:**
   - Identities -> Create Identity -> Domain
   - Add DKIM/SPF DNS records as instructed
3. **Request production access** (required to send to unverified recipients):
   - Account Dashboard -> Request Production Access
   - Describe use case: "Transactional workout plan delivery"
4. **Create SMTP credentials:**
   - SMTP Settings -> Create SMTP Credentials
   - This creates an IAM user; save the username and password
5. **Create SMTP credential in n8n:**
   - **Name:** `GymBot Email SMTP`
   - **Host:** `email-smtp.us-east-1.amazonaws.com` (use your region)
   - **Port:** `587`
   - **SSL/TLS:** `STARTTLS`
   - **User:** SMTP username from step 4
   - **Password:** SMTP password from step 4
6. **Update `fromEmail`** to any verified address/domain

**Cost:** $0.10 per 1,000 emails (essentially free at GymBot's scale)

## 8. Error Handling Matrix

The email branch is designed to be completely fail-safe. No failure in this branch should affect the main WhatsApp notification flow.

| Node | Error Type | Behavior | User Impact | n8n Execution Status |
|------|-----------|----------|-------------|----------------------|
| **GetWeek1WithExercises** | DB connection timeout | Branch terminates. `GenerateRoutineHTML` never executes. | No email sent. WhatsApp notification still delivered. | Workflow marked as success (parallel branch failure is non-blocking). |
| **GetWeek1WithExercises** | Empty result set (0 rows) | Returns empty array to `GenerateRoutineHTML`. | Email may be empty or not generated (depends on HTML template handling). WhatsApp unaffected. | Success. |
| **GetWeek1WithExercises** | SQL syntax error | Node throws error, branch terminates. | No email. WhatsApp unaffected. | Success (parallel branch). |
| **GenerateRoutineHTML** | JavaScript runtime error (e.g., undefined property access) | Node throws error, branch terminates. | No email. WhatsApp unaffected. | Success (parallel branch). |
| **GenerateRoutineHTML** | `ProcessUserPreferences` reference fails | Node throws error if `$('ProcessUserPreferences')` is not accessible. | No email. WhatsApp unaffected. | Success (parallel branch). |
| **HasEmail** | Email is `null` or `undefined` | False branch (index 1) -- dead end. No error. | No email (expected and correct behavior for users without email). | Success. |
| **HasEmail** | Email is empty string `""` | `exists` operator returns false. Dead end. | No email (expected). | Success. |
| **SendRoutineEmail** | SMTP authentication failure | `continueOnFail: true` catches the error. Workflow continues. | No email delivered. No error visible to user. | Success (error swallowed by `continueOnFail`). |
| **SendRoutineEmail** | SMTP connection timeout | `continueOnFail: true` catches the error. | No email delivered. | Success. |
| **SendRoutineEmail** | Invalid recipient email format | SMTP server rejects. `continueOnFail: true` handles it. | No email delivered. | Success. |
| **SendRoutineEmail** | Rate limit exceeded (e.g., Gmail 500/day) | SMTP server returns 429/rate limit error. `continueOnFail: true` handles it. | No email delivered. | Success. |
| **SendRoutineEmail** | Email sent but bounces | Node succeeds (SMTP accepted the message). Bounce occurs asynchronously. | User does not receive email. | Success. |

### Why `continueOnFail` Only on SendRoutineEmail

Only the `SendRoutineEmail` node has `continueOnFail: true`. The earlier nodes (`GetWeek1WithExercises`, `GenerateRoutineHTML`, `HasEmail`) do NOT need it because:

1. **Parallel branch isolation:** n8n executes parallel branches independently. A failure in one branch does not propagate to other parallel branches.
2. **Upstream node failures are fine to fail silently:** If `GetWeek1WithExercises` fails, the downstream nodes simply never execute.
3. **SendRoutineEmail is different:** It's the terminal node with external side effects (SMTP call). Without `continueOnFail`, a transient SMTP error would mark the entire workflow execution as failed in n8n's execution log, which creates noise and false alerts.

## 10. Rollback Plan

If the email feature causes any issues in production, it can be disabled instantly without code changes:

### Immediate Disable (< 30 seconds)

1. Open `WORKOUT_CREATOR` workflow in n8n UI
2. Click the connection line between "Create a row" and "GetWeek1WithExercises"
3. Delete the connection (press Delete/Backspace)
4. Save the workflow

**Result:** The 4 email nodes become orphaned (disconnected from the flow). They remain in the workflow but never execute. The existing WhatsApp flow is completely unaffected.

### Full Removal (Optional)

If a permanent removal is desired:

1. Perform the immediate disable above
2. Delete the 4 nodes: `GetWeek1WithExercises`, `GenerateRoutineHTML`, `HasEmail`, `SendRoutineEmail`
3. Save the workflow
4. Revert `"Create a row"` connections in the JSON to the original single-entry array

### Re-enable After Disable

1. Open workflow in n8n UI
2. Draw a connection from "Create a row" output to "GetWeek1WithExercises" input
3. Save the workflow

No other reconnection needed -- the internal chain (`GetWeek1WithExercises` -> `GenerateRoutineHTML` -> `HasEmail` -> `SendRoutineEmail`) remains intact from the original implementation.
